코드프레소 디자인 시스템 리뉴얼안

기존 코드프레소 디자인 시스템 기반 · 채널톡(channel.io) 벤치마킹 반영 · 2026-08-18 · "폰트가 작다"는 피드백을 핵심 개선축으로 삼아 본문 16px 체계는 유지하고 상위 위계 사이즈만 확대했습니다.

기존 코드프레소 시스템의 뼈대(폰트·컬러·스페이싱·라운드·섀도우·모션)는 이미 견고합니다. 리뉴얼은 새 시스템을 만드는 것이 아니라, 위계 표현력이 약한 지점만 정밀 보정하는 방향입니다. 채널톡에서 가져온 것은 톤(다채로운 액센트, 큰 라운드)이 아니라 구조(자간 공식, 3단 텍스트 위계, gap-first 레이아웃)입니다.

1폰트 시스템

서체는 그대로 Pretendard 단일 스택을 유지합니다. 변경하는 것은 서체가 아니라 스케일의 상단부입니다.

font-family: Pretendard, -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Malgun Gothic", sans-serif

유지 결정: Bold(700)를 쓰지 않는 절제된 톤은 코드프레소다움의 핵심이라 그대로 둡니다. 위계는 굵기가 아니라 사이즈 확대로 만듭니다 — 이번 리뉴얼의 핵심 변경점입니다.

2타입 스케일 — 실측 시스템 반영 (Heading / Body)

코드프레소 실제 타이포그래피 시스템은 Heading 9단 + Body 4단(각 2~3 weight)으로 이미 세분화되어 있습니다. 이전 초안의 "28/32/40/64" 4단 추정 스케일을 걷어내고, 이 실측 스케일로 교체합니다. 서체는 Pretendard(EN/KR) + Pretendard JP(일본어) 폴백을 병행 지원합니다.

최소 크기 가이드 본문은 16px을 기본 최소 권장, 부득이한 경우 14px까지 허용 — "작다" 피드백은 이 최소 기준 미준수 구간(12~13px 남용)에서 발생했을 가능성이 높음
이전 초안 정정: 앞서 "11·12·14·16·18·28·32·40·64" 4단 추정 스케일 및 자간 비례식(-1%)은 실측과 달랐습니다. 실제로는 Heading 9단 + Body 4단(× weight)의 훨씬 촘촘한 체계이며, 자간도 비례식이 아니라 -0.1px / -0.5px 2단 고정값입니다. "폰트가 작다"는 피드백은 스케일 자체보다 본문에서 16px 미만(12~13px) 사용 빈도를 줄이는 방향으로 접근해야 합니다.

3컬러 시스템

채널톡의 11-hue 액센트 시스템은 도입하지 않습니다. 코드프레소는 단일 브랜드 블루(#1A61EA)에서 파생한 단색 팔레트가 정체성이므로 그대로 유지하고, 기능상 꼭 필요한 상태색 3종만 최소 추가합니다.

클릭 — Segmented Control, 인디케이터 슬라이딩

탭 중 하나를 선택하면 검정 인디케이터가 클릭한 위치로 이동합니다. hover 배경은 --duration-hover(0.1s)로 즉각 반응하고, 인디케이터 이동은 --duration-indicator(0.25s)로 살짝 더 여유를 둡니다.

10컴포넌트 — 버튼

Primary(브랜드 블루 필박스) / Ghost(외곽선 보조 버튼) 2종. 크기는 기본(40px) / btn-lg(52px, CTA 전용) 2단. hover는 --duration-hover(0.1s)로 즉각 반응하며, Primary hover는 더 어두운 색이 아니라 브랜드 블루에 흰색을 섞은 더 밝은 색(color-mix(in srgb, var(--color-brand) 80%, white))으로 전환한다 — 눌렀을 때 무거워지는 느낌 대신 가벼워지는 느낌을 준다.

클래스 용도
.btn.btn-primary 주 강조 버튼 — 배경 --color-brand, hover 시 color-mix()로 밝게
.btn.btn-ghost 보조 버튼 — 배경 없음, border만, hover 시 텍스트/보더가 브랜드 컬러로
.btn-lg modifier — 높이 52px, 랜딩 CTA 등 강조가 필요한 자리에 .btn-primary와 함께 사용
재사용 원칙: 새 버튼이 필요할 때 색상을 새로 정의하지 않는다. Primary/Ghost 중 역할이 맞는 쪽을 그대로 쓰고, 크기만 .btn-lg 유무로 조절한다.

Pill CTA — 흰색 캡슐 배경 + 우측 원형 화살표 아이콘. 그라디언트/이미지 배경 위에 떠 있는 플로팅 CTA 버튼에 사용한다. hover 시 버튼 전체가 scale(1.03)으로 살짝 커진다.

클래스 용도
.btn.btn-pill 흰색 캡슐형 CTA — 높이 56px, 그림자로 배경 위에 떠 보이게 함
.btn-pill-icon 버튼 우측 끝 원형 화살표 배지(40px, 잉크 컬러 배경) — 별도 애니메이션 없이 버튼 전체 scale에 따라 함께 커짐
재사용 원칙: 텍스트+화살표 조합의 플로팅 CTA가 필요하면 새 pill 버튼을 만들지 않고 .btn.btn-pill을 그대로 쓴다. 아이콘 SVG는 위 예시의 M7 17L17 7M9 7h8v8(↗ 방향)를 재사용한다.

11컴포넌트 — 헤더 & 네비게이션

고정(fixed) GNB. 로고 + 1depth 네비게이션(드롭다운 트리거 포함) + 로그인/CTA 버튼 3단 구성. 배경은 투명하게 두어 아래 main 콘텐츠가 그대로 비치고, 테두리(border-bottom)만으로 경계를 표시한다. 스크롤을 내리면 위로 슬라이드아웃되어 숨고, 올리면 다시 슬라이드다운되어 나타난다(--duration-scroll/--ease-scroll).

규칙 값
전체 높이 75px (padding 16px 위아래)
1depth 네비게이션 드롭다운이 있는 항목은 <a class="nav-trigger">(+ chevron), 단순 링크는 <a class="nav-link"> — 둘 다 이동 가능한 요소이므로 button 대신 a 사용
hover 텍스트 컬러만 --color-brand로 전환 · --duration-hover(0.1s)
show/hide 모션 transform: translateY() 기반, .header.is-hidden 토글로 제어(JS: js/header-scroll.js)
재사용 원칙: 헤더의 CTA 버튼은 새 스타일을 만들지 않고 위 10번 버튼 컴포넌트(.btn.btn-primary / .btn.btn-ghost)를 그대로 가져와 쓴다.

12컴포넌트 — Hero & 설문 카드

랜딩 첫 화면. 상단 중앙 배너(.hero-banner) + 좌(카피/CTA) 우(설문 폼, 글래스모피즘) 2단 구성. 설문 카드는 본문 흐름과 독립적인 보조 콘텐츠이므로 <aside>로 마크업한다.

상단 배너

.hero-banner — 반투명 흰 필박스(rgba(255,255,255,.6)), hover 시 --color-surface로 밝아지며 --shadow-md로 살짝 떠오른다. 부모가 flex 컨테이너가 아니어도 자체를 display:flex; width:fit-content; margin-inline:auto;로 정중앙 정렬한다.

설문 카드 — 진행 표시

.hero-survey-progress는 그라디언트 채움 + 진행 끝 발광(glow) dot 패턴이다. 바는 linear-gradient(90deg, var(--color-brand-dark), var(--color-brand))로 채우고, dot(8px)은 흰 테두리 1.5px + 브랜드 컬러 glow로 은은하게 pulse한다. 뒤로가기 버튼(.hero-survey-back)은 배경·테두리 없는 순수 chevron 아이콘이며, 2번째 문항부터만 노출된다.

재사용 원칙: 이후 진행률 표시가 필요한 다른 폼(멀티스텝 폼, 온보딩 등)에도 이 그라디언트+glow dot 패턴을 그대로 재사용한다. 새로운 progress bar 스타일을 만들기 전에 이 패턴으로 충분한지 먼저 검토한다.

설문 카드 — 옵션 선택

.hero-survey-option이 선택되면(.is-selected) 배경이 linear-gradient(120deg, var(--color-brand-tint-2), color-mix(in srgb, var(--color-brand) 22%, var(--color-brand-tint-2)))로 밝은 톤으로 채워지고, 우측에 절대 위치(position:absolute)로 체크 아이콘이 겹쳐 나타난다. 선택하지 않은 나머지 옵션은 opacity:.45로 흐려져 시선을 모은다. 클릭 시 hero-survey-option-bubble 애니메이션(scale 1 → 1.025 → 1)으로 물방울처럼 은은하게 반응하고, 잠시 후 질문/옵션 블록 전체가 페이드+8px 슬라이드로 다음 문항으로 전환된다. survey 내부 트랜지션은 전역 --duration-scroll보다 50% 빠른 로컬 토큰 --survey-duration을 쓴다.

재사용 원칙: 옵션 선택형 UI(체크박스형 카드, 멀티 초이스 등)를 새로 만들 때 이 밝은 그라디언트 채움 + dim + bubble 모션 패턴을 우선 검토한다. 배경을 어둡게(--color-brand-dark 단색) 채우는 방식은 이 프로젝트의 선택 피드백 톤과 맞지 않으므로 지양한다.

함께하는 기업 로고 — 무한 가로 스크롤

.hero-clients는 hero 배경 위, .section-wrap 바깥에 이어 배치되어 hero의 그라디언트 배경을 그대로 공유한다. .hero-clients-marquee는 .section-wrap과 동일한 max-width로 폭을 맞추고, 로고 목록(.hero-clients-track)을 동일한 내용으로 2벌 나란히 두어 translateX(-100%) 애니메이션이 이음매 없이 반복되게 한다. 좌우 끝은 mask-image 그라디언트로 자연스럽게 페이드아웃시킨다.

재사용 원칙: 로고/뱃지 등을 무한 스크롤로 나열해야 할 때 새 마퀴 구현을 만들지 않고 이 트랙 2벌 + mask-image 패턴을 그대로 재사용한다.

13컴포넌트 — 섹션 타이틀

메인페이지 각 섹션 상단에 반복되는 라벨 + 타이틀 + 설명 3단 블록. .title 안에 .label(16px, 브랜드 컬러) → h2(44px, 전역 스타일 그대로 상속) → .desc(18px) 순으로 쌓인다. 기본 정렬은 중앙이며, 좌측 정렬이 필요하면 h2에 .text-left modifier를 추가한다.

핵심은 교육입니다. 외부 채용 대신, 내부 직원을 사내 FDE로 키우고, 진단이 숫자로 확인합니다.

클래스 용도
.title .label 16px, --text-body-16 · --color-brand
.title h2 44px, --text-h2(--text-heading-44) — base.css 전역 h2 스타일을 그대로 상속
.title h2.text-left modifier — 기본 중앙 정렬을 좌측 정렬로 전환
.title .desc 18px, --text-body-18 · --color-ink-light
재사용 원칙: 새 섹션을 추가할 때 타이틀 블록을 새로 만들지 않고 이 .title 마크업 구조를 그대로 복사해 텍스트만 바꾼다. h1(56px)은 페이지당 1회, 이 섹션 타이틀은 h2(44px)로 위계를 구분한다.

14컴포넌트 — 인사이트 카드 & 슬라이더

블로그·뉴스 글을 가로 슬라이드로 노출하는 카드. border를 쓰지 않고 배경색만으로 영역을 구분하는 것이 이 컴포넌트의 원칙이다 — 카드는 --color-surface-sunken, 썸네일 자리는 한 단계 진한 --color-surface-mist, hover 시 --color-brand-tint-2로 올라간다. 썸네일은 가로형(16:9) 고정이며, 트랙은 --container-medium 폭을 그대로 채우고 좌우 화살표만 position:absolute로 그 바깥 여백에 놓인다.

클래스 용도
.insight-slider 화살표의 position:relative 기준점. data-insight-slider 훅을 함께 붙인다
.insight-track-viewport / .insight-track 넘치는 카드를 잘라내는 창 / translateX로 밀리는 flex 트랙(gap --space-24)
.insight-card 한 화면 3장(1023px 이하 2장, 780px 이하 1장). 배경 --color-surface-sunken, radius --radius-lg
.insight-card-thumb 가로형 썸네일 자리. aspect-ratio:16/9 · 배경 --color-surface-mist로 이미지가 없어도 영역 유지
.insight-card-title h3에 붙는다 — 카드 안에서는 body 위계라 --text-body-18(18px)로 축소, 3줄 line-clamp
.insight-card-meta 카테고리 .tag + 날짜 time.text-caption. margin-top:auto로 카드 하단 정렬
.insight-nav.prev / .next 48px 원형 버튼. 선 대신 흰 배경 + --shadow-md로 구분하고, 끝에 닿으면 :disabled
재사용 원칙: 카테고리 라벨과 날짜는 새 클래스를 만들지 않고 공용 .tag·.text-caption을 그대로 쓴다. 제목(h3)은 카드 안에서 축소된 위계이므로 --text-body-18 토큰으로 override하며, 임의의 px 값을 직접 넣지 않는다.
