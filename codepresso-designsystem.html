서브페이지 첫 화면

Hero

서브페이지 첫 화면의 공통 골격입니다. 태그 + h1 + 설명(+ CTA)이 중앙 정렬되고, sunken 배경과 상단 브랜드 광원이 깔립니다. 보조 정보는 유리 띠 1장 안에 세로 구분선으로 나뉜 3칸(hero-facts)이 표준입니다 — 칸은 metric-card이고 안은 metric-card__value 20px + unit 14px + metric-card__label 14px입니다. 전용 클래스를 두지 않고 카드 슬롯을 그대로 쓰며, 수치형·질문형 모두 같은 마크업을 씁니다. 독립 카드로 늘어놓지 않습니다. hero 안에서는 그림자를 쓰지 않습니다(hover 제외). 메인 첫 화면(main-hero)과는 다른 컴포넌트입니다.

아이콘 크기

Icon Size

아이콘 크기는 이 세 클래스로만 정합니다 — icon-sm 20px(라벨 옆·GNB 항목·FAQ 화살표), icon-md 24px(기본, 카드·스텝), icon-lg 32px(한 칸의 주인공, hero 보조 밴드). 감싼 span에 붙이면 안쪽 그림이 따라옵니다. 배경이 있는 아이콘 박스(48px)는 크기가 다른 개념이라, 박스가 아니라 안쪽 그림에 붙입니다. 이 셋 말고 다른 크기를 만들지 않습니다. 박스와 그림은 짝으로 움직입니다 — icon-sm에는 32px 박스, icon-md에는 48px 박스.

07 · PATTERNS

화면을 만들 때의 순서

처음부터 예쁜 화면을 만들려고 하기보다, 정보의 순서와 필요한 패턴을 먼저 고르면 훨씬 빠릅니다.

  1. 01

    무엇을 가장 먼저 보여줄지 정합니다

    이 화면에서 사용자가 가장 먼저 알아야 할 한 문장을 고릅니다.

  2. 02

    내용에 맞는 섹션 배치를 고릅니다

    소개형, 좌우형, 스크롤 고정형 중 정보의 흐름에 가장 맞는 방식을 선택합니다.

  3. 03

    기존 컴포넌트에 내용을 넣습니다

    새 카드부터 만들기보다 Metric, Choice List, Preview 같은 공통 디자인을 먼저 사용합니다.

  4. 04

    색상은 강조가 필요한 한 곳에만 씁니다

    브랜드 블루는 행동을 유도하거나 중요한 변화를 보여줄 때만 사용합니다.

08 · MOCKUP MOTION

목업을 살아 있는 화면으로

제품 화면을 보여줄 때, 정지된 그림 대신 실제로 돌아가는 화면처럼 연출합니다. 읽어야 할 것만 텍스트로 남기고 나머지는 스켈레톤으로 가라앉힌 뒤, 확대·이동·pop으로 시선을 한 곳에 모읍니다. 여섯 가지 연출은 부모에 data-mock-motion 값만 바꿔 고릅니다.

F · 단계 진행

단계가 하나씩 켜진다 (stage)

나란히 놓인 단계 칸이 좌에서 우로 하나씩 등장하고, 칸 안의 요소가 이어서 올라오며, 칸과 칸 사이의 화살표가 다음으로 넘깁니다. 장면을 교체하지 않고 나란히 두는 것이 요점입니다 — 앞 단계의 결과가 뒤로 이어진다는 것은 세 칸이 함께 보일 때만 읽히기 때문입니다. 프로세스·확산·전후 흐름을 보여줄 때 씁니다.

09 · COMPONENT USAGE

AI에게 이렇게 요청하면 됩니다.

새 화면을 만들 때 처음부터 디자인을 설명하지 않아도 됩니다. 위에서 확인한 컴포넌트 이름과 넣을 내용, 배치 방식만 함께 전달하세요.

요청에 꼭 넣을 정보

  1. 사용할 컴포넌트예: Metric Card, Choice List, Preview Frame
  2. 배치 방식예: section-wrap row is-sticky
  3. 실제 콘텐츠제목, 설명, 버튼 문구, 수치, 이미지

그대로 복사해 쓰는 요청 예시

“Choice List와 Preview Frame을 활용한 교육 프로그램 소개 섹션을 만들어줘. section-wrap row is-sticky 구조로, 왼쪽에는 ‘우리 조직에 맞는 AI 교육’이라는 제목과 세 개의 프로그램 목록을 넣고, 오른쪽에는 각 프로그램의 화면 예시를 보여줘. 기존 컴포넌트 CSS와 hover 효과를 그대로 사용해줘.”
