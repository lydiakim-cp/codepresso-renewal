# 면·경계·그림자 3층 — 공간을 만드는 방법 (실측 기반)

> 2026-08, 외부 레퍼런스(TIGRIS류 SaaS 랜딩)를 **픽셀 단위로 실측**해 우리 체계와
> 비교한 결과다. 추측이 아니라 측정값이므로 그대로 따른다.
> 선례: `why-codepresso.html`이 이 방식으로 전환됐다(나머지 페이지는 순차 적용 예정).

## 결론 먼저

| | 배경 주체 | 카드 | 경계 | 평소 그림자 |
|---|---|---|---|---|
| **하지 말 것** | 페이지 한 장 | 흰색 | `--color-line` | 있음 |
| **할 것** | **섹션마다 번갈아** | 면으로 구분 | **없음** | **없음** |

**핵심은 세 가지다.**

1. **배경은 페이지가 아니라 섹션이 갖는다** — 흰 면과 틴트 면을 번갈아 둔다.
   페이지 한 장을 통째로 같은 면으로 깔면 섹션 경계가 사라져 전체가 한 덩어리로
   흐르고, 스크롤해도 "넘어간다"는 감각이 없다.
   옅은 면은 **`--color-brand-tint-2`(1.15)** 를 쓴다 — `surface-sunken`은 흰색과
   6% 차이뿐이라 경계가 안 보이고 `brand-tint-1`과 값이 같다(skills에서 같은
   실수를 했고 "허여멀건하다"는 지적을 받았다).
2. **경계는 선이 아니라 면이 만든다** — 판과 카드의 면이 다르면 테두리를 얹지 않는다.
   면과 선이 같은 일을 두 번 하면 화면이 도면처럼 읽힌다.
   **흰 섹션 위에 흰 카드를 두지 않는다** — 카드가 사라진다. 이때는 카드를 틴트로
   **가라앉힌다**(반대로 틴트 섹션 위에서는 카드를 흰색으로 띄운다).
3. **평소 그림자를 걷는다** — 그림자는 **상호작용 신호**다. 평소에도 떠 있으면
   화면이 탁해지고, 정작 hover했을 때 변화가 안 보인다.

## 여백과 폭 — "깔끔하다"의 절반

면·그림자를 다 맞춰도 레퍼런스만큼 깔끔해지지 않는다면 남은 건 이 둘이다.
**실측**: 레퍼런스 10789/1905 = **5.66** 페이지높이(섹션 8개),
당시 우리 7000/1440 = **4.86**(섹션 9개). 폭 대비 16% 더 여유롭고 섹션은 더 적다.

- **내용이 한 줄로 끝나는 섹션을 좁히지 않는다.** 공백이 남아 보여서 `padding-block`을
  96 → 80px으로 줄였는데 반대 방향이었다. 오히려 **벌려서** 숨을 준다(120px).
- **섹션마다 콘텐츠 폭을 바꾼다.** 우리는 9개 섹션이 전부 1208px 한 폭이라 리듬이
  없었다. 레퍼런스는 히어로 목업 거의 full-bleed / 스크린샷 안쪽 / **어두운 판은
  좁은 가운데 블록**(화면 폭의 40% 정도) / 카드는 중간 폭으로 계속 바꾼다.
  `.section-wrap`에 `max-width`를 얹어 섹션별로 조절한다.
- **어두운 판에 질감을 얹을 때 어둠을 잃지 않는다.** `opacity: .35`로 깔았더니
  판이 회청색(#535969)으로 들려서 "어둡다"가 안 읽혔다 → `.18`(#252D43).

## 제목 정렬 — 레퍼런스는 가운데다

앞서 "번갈아 준다"고 적었는데 **이 레퍼런스는 히어로만 좌측이고 본문 섹션 제목은
전부 가운데다.** 우리 다른 페이지들과 비교해서 내린 결론이었고 레퍼런스와는 맞지 않았다.

- **기본은 가운데.** 좌측은 **뒤에 오는 내용이 좌우 비대칭일 때만**(좌 텍스트 + 우 목업).
  가운데 제목 위에 좌측 정렬 콘텐츠가 오면 축이 어긋난다.
- 정렬을 섞는 것 자체가 목적이 아니다 — 내용 구조가 정한다.

## 아이콘은 `images/icon/`에서 고른다 — 그리지 않는다

`images/icon/ic_*.svg` **29개**가 프로젝트 아이콘 라이브러리다. SVG를 새로 그리기 전에
먼저 이 폴더를 본다. 특히 **제품 이름이 본문에 있으면 그 제품 아이콘이 이미 있다**
(`ic_axBuild` = AXpresso, `ic_skillFit`·`ic_skillPath`·`ic_skillCertify` = 역량 진단 계열).

인라인 방식은 `ax-build.html`의 관례를 따른다.

- **path만 가져오고 하드코딩 색을 토큰으로 바꾼다** — `#1A61EA` → `var(--color-brand)`,
  옅은 톤(`#A9C5F7`)은 `color-mix(in srgb, var(--color-brand) 35%, var(--color-surface))`.
- **40px 아이콘(`ic_skill*`)은 흰 판 + 테두리 프레임을 갖고 있다** — 카드 안 아이콘으로
  쓸 때는 그 두 `rect`를 빼고 안쪽 path만 24px 좌표로 옮긴다.
- 주석에 `<!-- ... — ic_{이름}.svg 기반 -->`으로 출처를 남긴다.

## 회전한 라벨 — 축 바깥에 두고, 폭을 못박는다

세로축 라벨처럼 `rotate(-90deg)`한 절대배치 요소는 두 가지를 함께 챙긴다.

- **판 안쪽에 두면 격자·데이터와 겹친다.** `transform-origin: left bottom` +
  `left`를 음수로 빼서 **판 바깥**에 세우고, 판에 그만큼 `margin`을 준다.
  가로축 라벨이 아래 바깥에 있으면 세로축도 왼쪽 바깥이어야 짝이 맞는다.
- **`width: max-content`를 준다.** absolute 요소는 폭이 없으면 쓸 수 있는 폭에 맞춰
  줄어들어 글자가 접힌다.
- **`getBoundingClientRect()`는 회전 후 박스를 준다** — 67×22 라벨이 22×67로 보인다.
  이 값을 보고 "줄바꿈됐다"고 판단하지 않는다(그렇게 오진해서 없는 버그를 고쳤다).

## 목업에 가장 진한 면을 준다

레퍼런스가 시선을 끌어가는 방식이다. **텍스트 영역은 조용히 두고, 제품 목업에
가장 진한 면을 준다** — 목업이 자기 카드와 같은 흰색이면 "카드 안의 또 다른
텍스트 블록"으로 읽혀 제품 화면이라는 신호가 사라진다.

```
섹션        흰색 / tint-2
└ 카드      한 단계
  └ 목업    ★ 가장 진한 면 (surface-deep 등)
    └ 내부  흰색 — "화면 속 콘텐츠"로 되돌린다
```

- **단계 차이를 두 열에서 같게 맞춘다.** 좌우로 카드가 나란히 놓일 때 한쪽만
  1.09×, 다른 쪽 1.19×면 두 열의 세기가 달라 보인다.
- **목업 내부 요소의 색을 확인한다.** `mock-ticker-chart`의 막대는 기본이
  `brand-tint-2`다 — 통을 흰색으로 칠하면 막대가 묻혀 **빈 상자**가 된다
  (실제로 그렇게 렌더됐다). 진한 목업 면 위에서는 막대를 흰색으로 올린다.

## 자주 하는 오해

- **"테두리를 없애야 깔끔하다"** → 아니다. 레퍼런스도 테두리를 쓴다.
  경계 픽셀을 스캔해 확인했다 — `흰색 → #E1E4EB 2px → 배경`으로 딱 떨어지고
  그림자 그라데이션이 없다. 깔끔함은 테두리를 뺀 데서 오지 않는다.
- **"대비를 세게 줘야 한다"** → 아니다. 레퍼런스의 카드/배경 대비는 **1.063×** 로
  우리 테두리 대비(1.180×)보다 오히려 약하다. 일관성이 세기를 이긴다.
- **"페이지 전체를 틴트로 깔면 된다"** → 아니다. 섹션 경계가 사라진다.
  배경은 **섹션 단위**로 번갈아 준다.
- **"옅은 면은 `surface-sunken`"** → 흰색과 6% 차이라 안 보인다. `brand-tint-2`를 쓴다.

## 밝은 면 ramp (흰색 대비)

```
surface        #FFFFFF  1.000×   카드
surface-page   #FBFCFF  1.026×
surface-sunken #F5F8FF  1.063×   ← 페이지 배경(레퍼런스 면적 53.7%)
brand-tint-2   #E9EFFF  1.150×
line           #EAECF3  1.180×
surface-raised #DDE5F3  1.267×   ← 틴트 페이지 위에 얹는 판·묶음
line-heavy     #D3D6E0  1.452×
surface-deep   #C6D3EA  1.510×   ← 밝은 면의 한계. 더 강하게 묶을 때
(어두운 판)     #04091A  19.6×
```

`surface-raised` · `surface-deep`는 이 실측에서 추가됐다 — 1.18×와 19.6× 사이가
비어 있어서 "판을 나눠도 허여멀건한" 문제가 있었다.

**이 두 면 위 텍스트는 `--color-ink` / `--color-ink-light`까지만 쓴다.**
`--color-ink-lighter`는 대비가 2.81× / 2.35×로 AA(본문 4.5) 미달이다.

## 3층 예시 — `why-codepresso.html` 02 섹션

```
페이지        surface-sunken  1.063×   ← 가장 아래
실패 판       surface-raised  1.192×   ← 가라앉은 판
우리 카드     surface(흰색)   1.063×   ← 떠오른 판
목업          surface(흰색)   카드 안
```

## 그림자 정책

```css
/* 나쁨 — 평소에 깔린다 */
.card { box-shadow: var(--shadow-sm); }

/* 좋음 — hover에만 */
.card { transition: box-shadow var(--duration-hover) var(--ease-hover); }
.card:hover { box-shadow: var(--shadow-md); }
```

**평소 그림자를 갖는 예외** — 화면 위에 실제로 떠 있는 것만.
`floating-cta`(따라붙는 배너) · `preview-frame`(제품 창) · `surface-glass`.

**그림자가 아닌 것** — 색 링(`box-shadow: 0 0 0 6px <색>`)은 지점을 표시하는
장식이므로 깊이용 그림자와 구분해서 남긴다(`timeline__marker`, 노드 링).

## 적용 순서

1. **섹션 목록을 적고 흰 면 / `brand-tint-2`를 번갈아 배정한다**(어두운 판 1개 포함)
2. 각 카드가 자기 섹션 면과 같은 색이 아닌지 확인한다 — 같으면 반대쪽으로 옮긴다
3. 면으로 갈렸으면 그 카드의 상시 `border`를 지운다
4. 상시 `box-shadow`를 hover로 옮긴다
5. **목업을 자기 카드보다 한 단계 진하게** 하고, 내부 요소는 흰색으로 되돌린다
6. 렌더해서 실제 픽셀을 찍어 단계 차이를 확인한다 — 눈으로 넘기지 않는다
