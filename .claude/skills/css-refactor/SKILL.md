# CSS 리팩터링 절차

`html-css-architecture`의 규범을 **이미 있는 코드에 소급 적용**하는 작업이다.
그 스킬(특히 0번 재사용 규칙, 0-1 "A를 B로 갈아탄다", `references/cleanup.md`)을 함께 읽는다.

## 0. 두 가지 원칙

1. **디자인을 남기지 않는다.** 두 곳이 조금이라도 비슷하면 하나로 합치고, 합칠 때는
   한쪽 디자인을 **버린다.** "기존 톤을 지키려고" 페이지 스코프에 옛 값을 남기면 정리가 아니다.
2. **지운 것은 기계로 증명한다.** 선언이 바뀌었는지 눈으로 판단하지 않는다 —
   `scripts/verify-declarations.py`를 돌려 **주석만 지운 단계는 `ALL OK`,
   규칙을 지운 단계는 의도한 파일에만 `DECL`** 인지 확인하고 넘어간다(7번).

## 1. 순서 (앞 단계 검증 전에 다음으로 넘어가지 않는다)

```
① 주석 정리 → 검증 → ② 중복 탐지 → ③ 마크업 통합 → ④ 다크/라이트 → ⑤ @media 병합 → ⑥ 브라우저 확인 → ⑦ 보고
```

커밋은 사용자가 요청할 때만. 단계마다 커밋을 나눌지 한 번에 할지는 사용자에게 묻는다.

## 2. 주석 정리

```bash
python .claude/skills/css-refactor/scripts/strip-comments.py
python .claude/skills/css-refactor/scripts/verify-declarations.py
```

남기는 것은 두 가지뿐이다.

- **파일 첫머리 2줄** — `/* Component: Cycle` + `어떤 영역인지 한 문장 */`. 2문장·각 줄 100자 이내.
- **페이지 CSS의 섹션 구분선 한 줄** — `/* 01 The Growth Loop */`.

지우는 것: 과거 시행착오·판단 배경·Markup API 예시·"왜 이 값인지" 설명. 전부 git 이력에 있다.

> 스크립트를 손볼 때 — `re.sub`의 치환문은 **반드시 r-문자열**로 쓴다. 백슬래시를
> 이스케이프한 일반 문자열은 백레퍼런스가 아니라 제어문자를 넣어 닫는 중괄호를
> 조용히 먹는다(실제로 9개를 잃었고, 중괄호 균형 검사로 겨우 잡았다).

컴포넌트 사용법은 코드 옆 주석이 아니라 `component-inventory.md`와
`codepresso-designsystem.html`이 갖는다 — 주석을 지웠으면 **인벤토리를 갱신한다.**

## 3. 중복 탐지 — 후보와 진짜를 가른다

```bash
python .claude/skills/css-refactor/scripts/find-duplicates.py 5
```

| 이것은 중복이 아니다 | 이것은 중복이다 |
|---|---|
| `display:flex; flex-direction:column; gap:…` 3줄이 여러 곳에 있는 것 | 한 컴포넌트의 구조를 다른 이름으로 베낀 블록(예: `journey-stage` → `diagnosis-preview-*`) |
| 토큰 이름이 같아서 겹쳐 보이는 값 | 두 페이지 스코프가 **같은 선택자 이름·같은 값**을 각자 갖고 있는 것(`.ax-build .outcome-arrow` = `.cases .outcome-arrow`) |
| 역할이 다른데 값이 우연히 같은 것 | 같은 타이포 3줄(14px/ink-light 등)이 클래스만 바꿔 4곳에 있는 것 |

판정은 **역할**로 한다. 값이 같아도 역할이 다르면 남기고, 값이 조금 달라도 역할이 같으면 합친다.
토큰은 이름이 아니라 최종 px 값으로 비교한다.

## 4. 마크업 통합 — 4개를 함께 움직인다

중복을 지우는 유일한 방법은 **한쪽 마크업을 다른 쪽 클래스로 바꾸는 것**이다. 한 세트로 처리한다.

1. **CSS** — 남길 쪽(공용 컴포넌트 · 토큰 · 유틸리티)에 규칙을 두고, 버릴 쪽 블록을 삭제한다.
   페이지에 남길 수 있는 것은 **컴포넌트 주석이 "사용 페이지가 정한다"고 명시한 값**(열 수·delay·판 높이)뿐이다.
2. **HTML** — 전 페이지에서 클래스를 교체한다. 상태 클래스도 남길 쪽 API를 따른다(`:last-child` 페이지 규칙 → `is-return`).
3. **JS** — `querySelector`가 버린 클래스를 잡고 있는지 본다. 통합 후 파라미터가 무의미해지면 그 파라미터도 지운다.
4. **`css/mobile.css`** — 반응형 수치를 **새 실제 크기로 다시 계산한다**(20px 기준 `-10px` → 36px 기준 `-18px`).

승격 위치 판단: 공용 컴포넌트 파일 → `components/ui/`, 텍스트/아이콘처럼 역할만 있는 것 →
`text.css`·`icon.css` 유틸리티, 색·간격 → `tokens.css`. **새 파일을 만들기 전에 기존 파일에 합칠 곳을 찾는다.**

작업 뒤 **죽은 클래스**를 훑는다(HTML·JS 어디에도 없는 CSS 클래스). 공용 API로 의도한 것일 수
있으므로 임의로 지우지 않고 목록을 만들어 사용자에게 확인받는다.

## 5. 다크/라이트 — 토큰 한 겹에서만 뒤집는다

- 하드코딩된 색·흰색 알파(`#1a5feadb`, `rgba(255,255,255,.55)`)는 **의미 있는 토큰**으로 올린다
  (`--color-glass-surface`, `--color-glass-line`, `--color-ink-on-dark` …).
- 다크 테마(`css/main-dark.css`)는 **그 토큰만 재정의**한다. 컴포넌트별
  `.main-dark .foo { background: … }` 반전은 토큰 재정의로 대체하고 지운다.
- 다크에서 `color-mix(…, white)` 리터럴을 쓰지 않는다 — 테마가 바뀌면 따라오지 못한다.
- **예외로 남기는 것**: 값의 차이 자체가 정보인 계단(`is-dark` 목업의 .04→.07→.11 오버레이 램프).
  3단 토큰으로 뭉개면 깊이가 사라진다. 남긴 이유를 보고에 쓴다.

## 6. `@media` 병합

- 브레이크포인트는 900/720/560 3단뿐이다. **연속으로 붙은 같은 쿼리 블록만** 합친다.
- 사이에 다른 쿼리가 끼면 멈춘다 — 건너뛰며 합치면 캐스케이드 순서가 뒤집힌다.
  (실제로 900px 블록이 뒤따르는 720px 내용을 삼킨 사고가 있었다. 병합 후 `@media` 개수와
  중괄호 균형을 반드시 다시 센다.)

## 7. 검증

```bash
python .claude/skills/css-refactor/scripts/verify-declarations.py   # ①단계는 ALL OK여야 한다
```

②~⑥단계에서는 **의도적으로 지운 파일에만** `DECL` 줄이 떠야 한다 — 손대지 않은 파일에
`DECL`이 뜨면 사고다. 목록을 실제 작업 파일과 하나씩 맞춰 본다.

그 다음 실제 화면. `.claude/launch.json`의 `static`(python http.server)으로 띄운다 —
`partials/`를 fetch하므로 `file://`로는 렌더되지 않는다.

- 8개 페이지를 전부 열어 **콘솔 에러 0**을 확인한다(라이트 4 + 다크 2 + 디자인시스템 + 메인).
- **캐시를 의심한다** — `?v=2` 같은 쿼리를 붙이지 않으면 방금 고친 마크업이 아닌 옛 DOM을 본다.
- 스크롤 연출·목업은 화면 밖에서 비어 보이는 것이 정상이다. 버그로 단정하지 말고
  `getComputedStyle`로 값을 직접 읽어 확인한다.
- 통합한 요소는 **통합 전후 계산값이 같은지** 숫자로 확인한다(font-size·line-height·color).
